# 将来構想：Coreから実行環境へAgentを配置する

2026-10-10。利用者との議論で将来検討に残した構想。I-03の実装範囲ではない。

利用者は、CoreがAgentをコンテナやOS仮想マシンへ配置し、結果を受け取る構成を考えている。
現在はGoでも実現可能な方向だと確認する段階に留め、実行環境・通信・配布方式の設計は将来検討する。
単一のgenericに外部role・tool構成・taskを渡す方式は、この配置方式と組み合わせられる。

想定する責務は、Coreが実行先の準備・起動・停止と履歴／会話採用を扱い、
環境内のgenericがmodelとtoolを使って作業し、進捗・実行証拠・結果をCoreへ返すことである。
Goの実行ファイルを環境へ配置して起動する方向が候補になる。
Go標準のプロセス起動・入出力接続は[os/exec公式文書](https://pkg.go.dev/os/exec)で確認したが、
hjhでコンテナ／OS VMへ配置する実証は行っていない。

現在のhjhは同じGo processでAgent loopを動かし、WorkerごとのQuickJS VMを使う。
将来構想の記録だけを根拠に、今回の実装へ汎用backend、remote API、コンテナruntime、
Guest通信protocolを先行追加しない。
具体化するときに、実際の利用環境、Agentの配布、toolが動く場所とworkspace、モデル接続、
進捗／履歴の転送、取消・終了待ちを改めて計画する。
