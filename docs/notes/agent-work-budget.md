# Agentへの作業予算と残量通知の案

記録日: 2026-10-16。利用者とのアイデアメモ。採用・実装は未決。

モデルに作業予算と残量を伝え、調査の優先順位や終了判断に使わせる案。
コンテキストウィンドウの空き容量とは別に、作業で消費するトークンの予算を扱う。
狙いは、必要な確認を済ませた後も探索や推論を広げ続ける挙動を減らし、
成果の有用性を保ちながら所要時間と消費量を改善すること。

## 最初に試す動作

- 親子合算で、推論を含む生成トークン数を計上する。
- 呼出し完了時にAPIが返したusageで残量を更新する。モデル自身の使用量の自己申告は使わない。
- 開始時と、残量が一定割合を下回った時にモデルへ通知する。
- 残量に応じて追加調査の優先順位を絞り、確認済みの結果と未確認事項を報告させる。

まずは通知による振る舞いの変化を比較する。予算値・通知割合・親子への配分・
予算到達時の扱いは未決で、自動停止の導入はこのメモでは決めない。
キャッシュされた入力の再送量と、新たに生成する推論・回答の量は分けて見る。

## 比較で観測したいこと

同じ課題・モデル・effortで、通知あり／なしを比較する。
所要時間、モデル呼出し数、親子合算の生成・推論トークン数に加え、
発見内容の正確さと有用性、必要な確認の取りこぼしを定性的に確認する。
予算への言及だけが増え、作業の進め方や終了判断が変わらない可能性も観測対象とする。

## 着想と参考

コードベースを確認する実利用で、Luna maxの探索子の一人が24分28秒・
33回のモデル呼出し・累計約6.1万推論トークンを使って完了した。
この一件だけでmaxや調査品質の優劣を決めず、通知の比較課題を考える材料とする。
