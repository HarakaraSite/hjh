# S-01：外部JSツールとGo実処理の接続スパイク

## 目的と範囲

READMEと2026-10-10の会話で合意した最初のスパイクを実施する。
固定の生成JS役コードから編集可能な外部JSツールを呼び、GoのHTTP・プロセス実行へ接続する。
結果の連鎖、並列実行、例外、キャンセル、処理の終了、次Workerへの編集反映を実測する。
親実行と内部呼出しを関連付けたJSONLを保存し、S-02の足場とする。

モデルへの接続、SQLite、Session採用・再開、製品API、TUI、他OSへの配布は今回の範囲に含めない。
JSONLは実験の観測記録であり、製品の履歴schemaを決めるものではない。

## 実験用の選択

- Go moduleは `spikes/s01/` 内に置き、製品本体の構成と分ける。
- bindingは `modernc.org/quickjs v0.25.0` を使用する。製品での採用は未決。
- Go本体とVMは同一プロセス。Workerごとに新しいVMを作る。
- Worker内では外部ツールと生成JSが同じVMを使う。
- VM操作は所有goroutineに限定する。HTTP・プロセス処理の結果はchannelでVMへ戻し、Promiseを完了させる。
- contextのキャンセルをVM割込み、HTTPリクエスト、プロセス停止へ接続する。
- 処理の終了を待ってからVMと実行記録を閉じる。
- 外部ツールはローカルES module。Go側loaderがファイルを読み込む。

## モジュールの責務

| モジュール | 責務 |
| --- | --- |
| `internal/trace` | 親子ID付きの開始・終了記録、未終了呼出しの収束、JSONL読戻し |
| `internal/host` | Go HTTP、OSコマンド、contextによる中断、プロセス終了待ち |
| `internal/jsruntime` | VM所有、module読込み、ツール登録、PromiseとGo処理の接続 |
| `internal/experiment` | ローカルHTTPサーバー、実行シナリオ、結果と後処理の観測 |
| `cmd/s01` | 実験実行、成果物保存、合否表示 |

## 観測する動作

- HTTP結果をJSで加工し、コマンドへ渡して結果を返す。
- Promise.allによる独立したHTTP呼出しが実際に重なる。
- JS例外、HTTPの接続失敗・非成功status、コマンドの非ゼロ終了がJS呼出し元へ届く。
- 処理を実行した後にJSが失敗しても、途中結果と観測した副作用が記録に残る。
- 同期JSループ、Promise継続内のJSループ、HTTP応答待ち、コマンド実行を停止できる。
- コマンドの子プロセスも停止し、HTTP handlerのcontext終了とGo処理の終了を観測する。
- 外部ツールを編集して同じバイナリから次Workerを起動すると、変更が反映される。
- 別WorkerのVM状態が混ざらず、同一Worker内の共有状態は観測できる。
- 返す集約結果とJSONL内の内部呼出しを別々に読める。

実験用HTTPサーバーとOSコマンドを実際に動かす。HTTPサーバーは外部serviceの仕様を模倣するfixtureではない。
キャンセルは対象処理の開始を観測してから行う。実験全体の待機上限は、終了を確認できないケースを
未成立として報告するための測定用watchdogであり、製品の実行上限を定義しない。

## 出力と判断

各シナリオのJSONL、集約結果、所要時間、処理終了・後処理の観測を保存する。
VM共有・分離とキャンセルの成立範囲、未確認事項、bindingの制約を結果文書に記載する。
HTTPとコマンドの結果の連鎖、例外伝播、対象処理のキャンセルと終了が成立すれば、今回のS-01経路を成立とする。
S-02全体、S-03全体、S-04、S-05はこの実験だけで成立とはしない。
