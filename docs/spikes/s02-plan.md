# S-02：SQLiteによる内部ツール実行履歴の保存

## 目的と範囲

S-01で成立した生成JS・外部ツール・Go実処理の経路を使い、内部呼出しの履歴をSQLiteへ保存する。
親コード実行が失敗・中断しても、保存済みの開始・結果・失敗と親子関係を読み戻し、
モデルへ返す集約結果と内部処理の証拠を別々に確認できることを検証する。

今回の会話で合意した範囲は、正常終了、失敗、キャンセル、プロセス途中終了時の実行証拠と副作用の確認。
会話への採用、Session再開、使用構成の全保存、長期履歴のprojectionはS-04で扱う。
製品のDB schemaや異常終了回復方式をこの実験だけで確定しない。

## 実験構成

- 実行経路の複製を避けるため、S-01のGo module内に `cmd/s02` を追加する。
- `internal/trace` は開始・終了・親子IDを所有し、保存先のSinkへeventを渡す。
- `internal/history` はSQLiteへの保存、読戻し、既に停止を確認した指定runの状態収束を担う。
- `internal/historyexperiment` は実行シナリオ、別プロセスのreader・writer、停止境界の観測を担う。
- SQLiteドライバは `modernc.org/sqlite v1.60.1`。binding同様に実験用の選択。
- SQLiteの実験設定はWAL、synchronous=FULL。各eventをtransactionでCOMMITしてから観測通知を返す。
- run IDとrun内call IDを組み合わせ、複数Workerの履歴を区別する。
- 既存eventは変更・削除せず、状態の読戻しはeventから導出する。

## 観測する動作

1. 生成JSから外部pipelineツール、内部HTTP・commandツール、Go処理を呼び、親子関係と集約結果を保存する。
2. 内部コマンドの成功後にJSを失敗させ、成功した処理、実際に書いたファイル、親の失敗を読み戻す。
3. コマンド失敗の終了コード・stdout・stderrと、外部ツール・親の失敗を別々に読み戻す。
4. ファイルを書いて待機するコマンドをキャンセルし、途中の副作用と保存されたキャンセル結果を確認する。
5. 2Workerを同じDBへ並行記録し、runごとの親子IDと結果が混ざらないことを確認する。
6. 別プロセスwriterで内部コマンドの成功をCOMMITした後、親のJS完了前にSIGKILLする。
   別プロセスreaderで既存の成功記録を読み、親の未終了と区別する。
7. 実際のファイル書込み完了後、host結果をINSERTしたtransactionのCOMMIT前にwriterをSIGKILLする。
   生存中のwriterと終了後の両方を別プロセスreaderで読み、未COMMITの結果が見えないこと、
   副作用は存在するのに保存履歴からは成功を確定できないことを観測する。

途中終了実験の停止境界は実験専用hookで通知する。SQLite・JS・OS処理自体は実際に実行する。
停止したwriterは `Wait` で終了を確認する。再Openや閲覧だけで未終了のrunを変更しない。
明示的な収束操作は、実験側が停止を確認したrunだけを指定して行い、根拠をeventへ残す。
親executionには `interrupted`、結果の保存を確認できない内部呼出しには `outcome_unknown` を追記する。
外部副作用とDBのCOMMITは別の操作であり、履歴だけから副作用の不在や完了を推測しない。

## 成果物と成立基準

- 再現可能な `cmd/s02`、保存先を切り替えた既存実行経路、SQLite保存・読戻しの実装。
- 実際のSQLite DB、別プロセスから読んだevent・call状態、集約結果、ファイルの副作用、停止境界の記録。
- SQLite依存のversion/checksum、実行条件、成立範囲と未確認事項を記載した結果文書。

保存済みの親子記録・結果・失敗を正常終了、失敗、キャンセル、途中終了後に読めること、
未COMMITの結果と既に観測できた副作用を区別できることを、今回のS-02の成立基準とする。
プロセスのSIGKILLは電源断・ディスク故障の実証ではない。全使用構成、会話採用、Session再開は今回確認しない。
