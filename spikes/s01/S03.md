# S-03 JSライブラリ・外部tool／hookと依存配布

YAMLの依存一覧をHTTPで取得し、`yaml` で解析、`semver` で候補を照合して、
GoのファイルAPIでJSONレポートを保存・読み戻す。生成JSからworkflowと内側ツールを呼び、
それぞれ外部hookとSQLiteの履歴へつなぐ。

## 実行

このGo moduleのディレクトリで実行する。Go 1.27以降、Linuxが必要。
prepared vendorをリポジトリへ保管しているため、初回Go module取得後のS-03実行にはNode／npmは不要。
HTTPは実験CLIが起動するlocalhostサーバーへ接続する。モデルAPIは呼ばない。

```sh
go build -o ../../dist/s03 ./cmd/s03
../../dist/s03 -out ../../dist/s03-observations
```

`-tools` の既定値は `s03-tools`。`-out` へSQLite、view、report、summaryを保存する。
`-package-out` の既定値は `../../dist/s03-packages`。runごとのサブディレクトリへ配布コピーを置く。
同じ保存先への再実行はDBへ新しいrunを追記し、シナリオごとのviewとsummaryを更新する。
tool・hook編集は一時コピーと配布コピーへ行い、元ソースは変更しない。

```sh
go vet ./...
go build -race -o ../../dist/s03-race ./cmd/s03
../../dist/s03-race -out ../../dist/s03-race-observations
```

## 依存の取得と準備

`s03-deps/` で以下を実行する。Node、npm、npm registryへの接続が必要。
version・配布URL・integrityは `package-lock.json` に固定している。

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run vendor
```

準備scriptはyamlのbrowser ESMを相対importの木ごとコピーし、semverのCommonJSを
esbuildでneutral ESMへ変換する。両ライブラリのISC licenseを保管し、vendor各fileのhashとbytes、
依存の取得元、esbuildの入力・出力metadataを残す。
tool・hookのソースはbundleへ含めない。tool／hookの編集にはこの準備やGo再buildは不要。
依存のversionやbundle内容を変更する場合は、lockとvendorを更新して配布する必要がある。

## モジュールと実験契約

| 場所 | 責務 |
| --- | --- |
| `s03-tools/index.js` | 登録ツール、workflowとHTTP／ファイル操作の合成 |
| `s03-tools/modules/catalog.js` | YAML・semverで依存一覧を加工 |
| `s03-tools/hooks.js` | YAML設定をGo APIで読み、引数と返却結果を変更 |
| `s03-tools/vendor/` | 準備済み依存、license、hash、bundle metadata |
| `s03-deps/` | npm取得の固定とvendor準備 |
| `internal/host/file.go` | UTF-8テキスト相当のfile read／writeをGoから提供 |
| `internal/jsruntime/bootstrap.js` | tool合成・hook呼出し・Go非同期APIのJS接続 |
| `internal/libraryexperiment/` | 実HTTP、実ファイル、source編集、互換範囲と配布コピーの観測 |
| `cmd/s03` | 実験全体または配布Workerの起動 |

hookはこのスパイクで選んだ外部moduleだけをWorker起動時に読み込む。
`beforeTool({name,args},api)` が新しいargs、`afterTool({name,args,result},api)` が新しいresultを返す。
前者・後者は内側ツールにも適用する。失敗したtoolにはafterToolを実行せず、例外を呼出し元へ返す。
hook自体も履歴のcallとなり、hookからのGo APIはその子に記録する。製品の最終hook契約ではない。

ファイルAPIは `api.readFile({path}) → {path,text}` と
`api.writeFile({path,text}) → {path,bytes}`。親ディレクトリは呼出し側が用意する。
今回の用途はテキストファイルであり、binary・stream・rename・directory操作などは公開していない。

配布WorkerのCLIは `-worker -tools EXTENSIONS -db DATABASE -run RUN_ID -input INPUT_JSON`。
実験全体ではこのmodeを別プロセスで起動し、PATHを空ディレクトリにする。
配布コピーのinputは実験サーバーの一時URLを含むため、保存コピーの再実行にはURLを更新する。
通常binaryは今回のbuild環境のlibcへ動的にリンクしている。他OSやlibcを含む起動条件の確認はS-05へ残す。
