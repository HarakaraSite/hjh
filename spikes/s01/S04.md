# S-04 Session・会話採用・構成追跡と範囲読込み

S-03のHTTP・YAML／semver・Goのfile処理をSession内で実行し、
実行証拠と会話への採用を分けて保存する。実験の生成JSは固定コード、回答draftは実結果から作る。
実LLMは呼ばない。

## 実行

このGo moduleのディレクトリで実行する。Go 1.27以降、Linuxが必要。
初回Go module取得にはネットワーク接続が必要。prepared JS依存はS-03のものを使い、
HTTPはCLIが起動したlocalhostサーバーへ接続する。Workerの実行にNode／npmは使わない。

```sh
go build -o ../../dist/s04 ./cmd/s04
../../dist/s04 -out ../../dist/s04-observations
```

`-tools` の既定値は `s03-tools`、`-work` は `../../dist/s04-work`。
元の外部tool treeを作業用にコピーし、さらに各構成のsnapshotからWorker用のfile treeを展開する。
元の `s03-tools` は編集しない。snapshotはDBへ保存し、作業用treeも残す。
`-out` へDB、構成archive、execution、inspection、summaryを保存する。
同じDBで再実行すると別のSessionとrunを追加し、シナリオごとのJSONは今回の観測へ更新する。

`-history-turns` は履歴増加実験の追加実行数。既定値120は測定条件であり、製品上限ではない。
会話window・turn pageにはこの実験で3件を指定する。

```sh
go vet ./...
go build -race -o ../../dist/s04-race ./cmd/s04
../../dist/s04-race -out ../../dist/s04-race-observations
```

## 閲覧と再開

Session IDはsummaryにある。以下は読み取り専用の別プロセスで会話とturn pageを閲覧する。

```sh
../../dist/s04 -inspect -db ../../dist/s04-observations/history.sqlite -session SESSION_ID -count 3
../../dist/s04 -inspect -db ../../dist/s04-observations/history.sqlite -session SESSION_ID -before POSITION -after TURN_ORDINAL -count 3
```

`-before` は会話positionの排他的な上側cursor（0は最新）、`-after` はturn ordinalの排他的な下側cursor。
会話は採用済みだけ、turn pageは成功・失敗・キャンセル・未採用を含む。
会話windowは選択した範囲を古い順に返す。turn pageはordinalの昇順。
inspectionにあるSession全体の件数はSQL集計であり、event本文を全件読み戻す操作ではない。

保存Sessionを現在の構成で再開するCLI：

```sh
../../dist/s04 -worker -db DATABASE -session SESSION_ID -turn NEW_TURN_ID -settings CURRENT_SETTINGS_JSON -work WORK_DIRECTORY -url YAML_SERVICE_URL -path REPORT_PATH -count 3
```

settingsは `model`、`instruction`、`extensions`（外部treeへのpath）、`hooks`（tree内の相対file path）を持つ。
外部treeには `hook-config.yaml` を置き、S-03のhookがそれを読む。
実験で使ったURLは一時サーバーのものなので、後からCLIを再実行する場合は稼働中サービスのURLに更新する。
reportの親ディレクトリは呼出し側で用意する。

再開Workerは現在の設定をcaptureし、保存・展開したソースを使う。過去の構成を自動復元して実行する方式ではない。
採用済み会話から取り出したmessagesと現在のinstructionを入力候補として記録し、固定の生成JSにも渡す。
成功した実行と回答draftを保存後、別transactionで会話へ採用する。

## 所有する状態と操作

| 場所 | 責務 |
| --- | --- |
| `internal/configsnapshot` | 設定、外部file tree、Go依存・binary hashのcaptureと保存bytesの展開 |
| `internal/history/configuration.go` | 構成descriptor・source bytesの永続化と選択した構成／fileの読戻し |
| `internal/history/session.go` | Session、turn、実行終了結果・回答draft、明示的な採用marker |
| `internal/history/window.go` | 会話window、turn page、指定runのevent page、query plan |
| `internal/session` | Workerの構成準備、履歴からの入力候補、実処理、終了保存と会話採用 |
| `internal/sessionexperiment` | 成立観測、reader／writerプロセス、採用停止境界、履歴増加と計測 |
| `cmd/s04` | スパイク、閲覧、再開Workerの起動 |

実行eventはS-02と同じhistoryが所有し、会話本文は保存turnを採用markerで選択する。
構成は内容から導いたIDで参照し、同じ構成をturnごとに複製しない。
snapshotには外部treeの全fileを保存するが、会話windowにsource bytesや全eventは含めない。
file内容を保存する対象は、この実験の外部treeであり、一般的な環境全体を自動収集する方式ではない。

採用COMMIT前の停止は実験が起動したwriterだけへSIGKILLし、Waitで終了を確認する。
readerは閲覧時に自動採用・修復を行わない。実験の時間監視は未終了検出用で、製品の実行時間契約ではない。
