# S-02 履歴保存スパイク

S-01と同じ生成JS・外部ツール・GoのHTTP／OSコマンドを実行し、SQLiteへ実行証拠を保存する。
Go moduleと実行経路の複製を避けるため、このディレクトリに `cmd/s02` を置いている。

- [結果と成立範囲](../../docs/spikes/s02-results.md)
- [観測記録](../../docs/spikes/s02-artifacts/summary.json)

## 再現

このディレクトリで実行する。Go 1.27以降、Linux、`sh`、`tr`、`sleep` が必要。
初回buildはGo module取得のためネットワークを使う。実験のHTTP通信はlocalhostで完結し、モデルAPIは呼ばない。

```sh
go build -o ../../dist/s02 ./cmd/s02
../../dist/s02 -out ../../dist/s02-observations
```

`-tools` は外部JS moduleディレクトリ、`-out` はDBと観測ファイルの保存先。
同じ保存先で再実行すると、新しいrun IDでDBへ追記する。前のrunと副作用ファイルは残り、
`summary.json` とシナリオごとのview JSONは今回の結果で更新される。

`summary.json` のrun IDを指定すると、別プロセスから読み取り専用で履歴を確認できる。

```sh
../../dist/s02 -inspect ../../dist/s02-observations/history.sqlite -run RUN_ID
```

通常実行・race detectorによる実行とも、同じ実処理と保存・読戻しを照合する。

```sh
go vet ./...
go build -race -o ../../dist/s02-race ./cmd/s02
../../dist/s02-race -out ../../dist/s02-race-observations
```

途中終了シナリオは、この実験が起動したwriterだけを指定した保存境界でSIGKILLし、`Wait` で終了を確認する。
8秒のwriter監視と5秒のreader監視は実験の未終了を検出するための時間であり、製品契約ではない。

## 責務

| 場所 | 所有する状態と操作 |
| --- | --- |
| `internal/trace` | run内call ID・親子関係・event順序とSinkへの記録 |
| `internal/history` | SQLite接続・run登録・event保存・読み取りview・停止確認済みrunへの状態追記 |
| `internal/historyexperiment` | シナリオ、実副作用の読戻し、別プロセスreader／writer、COMMIT前後の停止観測 |
| `cmd/s02` | 実験、reader、writerの起動 |

`internal/jsruntime`、`internal/host`、外部 `tools/index.js` はS-01と共有する。
既存eventを更新せず、保存済みeventからcall状態を導出する。副作用ファイルは実験の観測資料であり、
DBだけから外部世界の状態を確定できるという意味ではない。
