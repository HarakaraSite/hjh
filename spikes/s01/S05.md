# S-05 Linux配布・起動

- [計画](../../docs/spikes/s05-plan.md)
- [結果](../../docs/spikes/s05-results.md)
- [実行記録](../../docs/spikes/s05-artifacts/summary.json)

`cmd/s05` はS-04のSessionとS-01〜S-03のruntimeを共有する配布用CLI。
追加した操作はcreate／run／adopt／inspect。固定JSを使い、モデルAPIは呼ばない。
tool／hook／vendorは本体の外に置く。

## 配布物を作る

このGo moduleのディレクトリで実行する。Go 1.27以降、Python 3、readelfを使う。
Go依存とS-03のprepared vendorが必要。vendorを作り直す場合は [S-03の手順](S03.md)に従う。

```sh
python3 s05/package.py
```

出力JSONのarchiveがtar.gz。`../../dist/s05-packages/build-*/` に本体とarchiveを置く。
既存packageは消さず、毎回別のbuild directoryを作る。
本体のbuildはCGO_ENABLED=0、linux/amd64、GOAMD64=v1、trimpath。
license、Go build情報、JS依存情報、file hashを一緒に配布する。
外部JSを編集してもGo本体は再ビルドしない。

利用者向け操作は [配布物のREADME](s05/README-package.md)にある。
tar.gzを展開後、提供するYAML serviceのURLで実行する。
初回観測時のlocalhost URLは検証中のみ有効なので、後から使う場合は稼働中のURLを指定する。

## 空rootで起動する

検証hostはLinux/amd64、Python 3.12以降、sudo／chroot、openssl、lddを必要とする。
sudo -nでchrootを起動できる環境で行う。

```sh
python3 s05/verify.py ../../dist/s05-packages/build-XXXX/hjh-linux-amd64.tar.gz --out ../../dist/s05-observations
```

verifyはarchiveを新しいrootへ展開し、chroot内でuid／gidを現在の利用者へ切り替えてCLIを起動する。
hostの既存設定を書き換えず、mountは行わない。新しいrootと実行証拠は残す。
`--work` の既定は `../../dist/s05-work`、`--out` の既定は `../../dist/s05-observations`。
outのJSONは今回の観測へ更新するが、実行rootは毎回新規作成する。

検証用HTTP／TLS serverはhostのPythonが起動する。
最初はrootに外部program・共有library・CA・DNS設定を入れず、IP宛てHTTPとSQLiteを確認。
次にtool／hook／instructionを編集して再開する。
HTTPS確認では検証用CAとhostsを追加し、外部HTTPSではhostのCAとresolv.confを追加する。
追加commandはまず未導入を記録してから、hostのechoとlddが示すruntime依存だけを追加する。
openssl、Python、sudo／chrootはrootの外にあり、配布CLIがそれらを呼ぶことはない。

CLIの実行監視40秒は検証の未終了検出用で、製品の実行時間契約ではない。
外部HTTPS検証は `https://bellard.org/quickjs/` の到達性を使う。
途中で不成立になればJSONとrootが残り、summaryは全シナリオ成立時に保存される。

## 所有する責務

- `cmd/s05`：操作flag、package path、state path、既存Sessionへの接続、出力。
- `internal/session`／`history`／`configsnapshot`／`jsruntime`／`host`：既存処理を共有し、S-05では変更しない。
- `s05/package.py`：ビルド、配布fileと依存notice収集、manifest、tar.gz作成。
- `s05/verify.py`：展開物からの実行、実service、編集、追加OS資源、観測。

確認コマンドは `go vet ./cmd/s05`。GoformatとPython構文も確認する。
静的配布物の実行が今回の検証対象であり、別のrace binaryを配布物の代替にしない。
